## Deviations from T7 / MASTERPLAN (and why)

1. **`repo_count` = 21, not 24.** GraphQL is unreachable here and the v1 cache never stored `totalCount`; 24 exists only in BRIEF.md. By T7's own rule (upright only if the build can point at the measurement) the chart number is what was surveyed; `unsurveyed[]` is therefore empty. First live run with a token will move it to 24 and fill `unsurveyed` (MASTERPLAN risk 9: check by hand). `checks/data.py` warns when `repo_count != surveyed + unsurveyed`.
2. **`account_since` is month-precision (`2024-10`)**: the v1 cache kept only "Oct 2024"; schema allows `YYYY-MM(-DD)?`; GraphQL will restore the day.
3. **Sweep threshold** = `max(2, min(5, ceil(n/3)))` — the orchestrator's "≥ 5 repos" and T7's "≥ ⅓" reconciled as the looser rule (5 for 21 repos), floored at 2. Four sweep days found (9–10 Nov 2025, 1 and 7 Oct 2026).
4. **`weeks[].days`** = distinct commit-days in the week across the fleet (≤ 7), not repo-days; per-repo `week_days[52]` keeps the repo view.
5. **Extra keys** (all inside my schema): `repos[].days` (the commit-day primitives, so derive() can rerun from the file), `repos[].week_days`, `repos[].tz_offsets`, `repos[].stale_branch_count` (the list itself is kept only for the harbour repo — game_engine has 196 stale bot branches), `provenance.instruments`/`graphql_at`, `variation.min_basis_days`, `sweep_threshold`, `tide.hw.cause_share`, `tide.slack.n`, `calendar_weeks`, `edition.uploads`, `notices[].n/body/cite`, `corrections` entries carry `date` and `title` (the task asked for first line + date), `languages[].bytes`.
6. **REST as a partial instrument**: repo-scoped REST answers only for the three repos this session is bound to, so `languages[]` keeps the cached GraphQL shares (a 3-repo byte sample is not "by bytes") and `instruments.rest="partial"`; per-repo `stars/language/archived` are filled only where REST answered. In Actions (unbound token) REST covers every repo and becomes `live`.
7. **`cache-failed`**: `validate(..., allow_failed=True)` lets build_stats re-stamp; `check.py`/plug-in never pass it, so the file fails CI as decision 16 wants. Corrupted cache → `SystemExit` 1, nothing written.
8. **The log's `date` is kept** from the existing computed log on later runs (a computed session should not look re-run daily); `version` follows `edition.version`.
9. **Followers/stars** are schema-only and stale (cache 46/0; Rust-sitemap and Scrapy now have 1 star each per REST) — not printed anywhere by decision, left for GraphQL.
10. `tide.hw` is allowed to be the trailing week (only `lw`/`median`/`slack` exclude it, as T7 specifies). Today that makes the HW the 7 Oct sweep (358, Data_science_dev 1 day) rather than the January game_engine sprint (296, 278 of them game_engine). Sheet copy should expect a one-day cause.
